# 大活动管理（skill 组入口）

本 skill 只做意图识别与路由，不重复成员 skill 的流程细节。成员文件位于同级目录（即 `~/.claude/skills/` 下）：

| 成员 | 负责 | 位置 | HITL |
| --- | --- | --- | --- |
| `act-mcp-combined-create` | 一次创建 1 个大活动 + N 个商品活动 | `../act-mcp-combined-create/SKILL.md` | 完整参数预览后必须确认 |
| `act-mcp-big-activity-update` | 部分更新大活动字段 | `../act-mcp-big-activity-update/SKILL.md` | 差异预览后必须确认 |
| `act-mcp-big-activity-delete` | 删除大活动并级联删除商品活动 | `../act-mcp-big-activity-delete/SKILL.md` | 影响预览后必须确认 |

路由后**读取对应成员的 SKILL.md 并按其状态机执行**。在 Claude Code 中可直接用 Skill 工具加载成员；其它 agent 用文件读取，行为一致。

## 路由决策

| 用户意图 | 去向 |
| --- | --- |
| 新建大活动，同时带商品列表 | `act-mcp-combined-create` |
| 只新建一个大活动，没有商品 | 直接用 `create_big_activity` 工具，不加载成员 |
| 修改已有大活动的字段 | `act-mcp-big-activity-update` |
| 删除整个大活动及其商品 | `act-mcp-big-activity-delete` |
| 给已有大活动追加商品 / 删除单个商品活动 | `create_product_activity` / `delete_product_activity`，不属于本组 |
| 查询或统计 | `list_big_activities` / `get_big_activity` / `get_activity_stats`，不属于本组 |

判断顺序：

1. 先确认是**写操作**且对象是**大活动**；否则不进入本组。
2. 判断动作是“建 / 改 / 删”。
3. 动作与对象都明确时，直接进入成员 skill，不再向用户反问“你想做什么”。

## 组内公共契约

以下规则三个成员一致；成员内部有更细的说明时以成员为准。

### 目标定位

- 用户给 ID → 直接 `get_big_activity` 校验存在性。
- 用户给名称 → `list_big_activities(keyword)` 搜索；命中多条时必须列出候选让用户用 ID 指定，不能默认取第一条。
- 用户指代模糊（“最近那个”“刚才建的”）→ 先查询候选再让用户选，不推断。

### 参数映射

```
actType:     1 满减 | 2 折扣 | 3 秒杀 | 4 优惠券 | 5 组合优惠
audience:    ALL 所有用户 | NEW 新客
time:        yyyy-MM-ddTHH:mm
budget:      单位元，≥0，≤ 999999999999.99，2 位小数
poiId/skuId: 64 位正整数，字符串传递
operator:    ≤50 字符，默认 mcp-agent
```

### HITL 底线（新建 / 编辑 / 删除）

- 创建意图、修改意图、删除意图都不等于批准。
- 必须先预览（新建看完整入参与商品明细，编辑看 before→after，删除看目标与级联影响），**预览与写入不能在同一轮**。
- 只有用户在预览之后明确确认（含“确认创建/确认修改/确认删除”语义且指向预览目标）才提交。
- 含糊回复只追问一次；用户取消则明确告知“未写入任何数据”并停止。
- 即使用户要求“直接建/直接改/直接删，不用确认”，也要完成一次预览 + 明确确认。
- 确认时附带参数修改的，按新参数重新预览并重新确认。

### 失败与复核

- 写入失败时说明是否发生部分变更；新建、编辑和删除都是单事务，失败即回滚。
- 写入成功后用 `get_big_activity` 复核结果；复核异常时如实说明，不掩饰。

## 何时反问

只在以下情况打断用户：

- 动作不明确（“调整一下中秋节4”——改什么、还是删？）；
- 目标不唯一（同名或关键字命中多条）；
- 关键参数缺失或冲突（结束时间早于开始时间等）。

用户已经说清楚时直接路由，不做多余的意图确认；写入前的 HITL 预览与确认仍必须执行。
