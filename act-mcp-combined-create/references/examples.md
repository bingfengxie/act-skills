# 交互示例（用于对齐输出风格）

## 示例 1：分轮补齐缺失参数

**用户**：组合创建活动

**助手**：请提供以下信息（可直接按模板填写）：

```
name:                活动名称
actType:             1=满减 / 2=折扣 / 3=秒杀 / 4=优惠券 / 5=组合
startTime:           yyyy-MM-ddTHH:mm
endTime:             yyyy-MM-ddTHH:mm
audienceScope:       ALL（全部）/ NEW（新客）
budget:              预算（元）
productActivities:   至少 1 条（poiId 必填，skuId / upc / productDiscountJson 可选）
```

**用户**：活动名称：中秋节4 / 活动类型：折扣 / 开始时间：2026-8-20 00:00

**助手**：收到，已记录：

- 名称：中秋节4
- 类型：2（折扣）
- 开始时间：2026-08-20T00:00

还缺 4 项必填信息：

1. **结束时间**（需晚于开始时间）
2. **活动人群**：ALL 或 NEW
3. **预算**（元）
4. **商品列表**（至少 1 条：poiId 必填）

**用户**：结束时间：2026-8-25 23:59 / 人群：全部 / 预算：1212 元

**助手**：已记录，时间校验通过。只剩商品列表，请按此格式提供：

```
商品1:
门店ID：必填
skuID：可选
upc：可选
商品折扣json：可选，默认 {}
```

**用户**：商品1：门店ID 10003，skuID 3333，upc xxxx33，商品折扣json {"price":0.7}；商品2：

**助手**：商品1 已记录。商品2 还缺门店ID；如果只创建商品1，回复“只创建商品1”。

**用户**：只创建商品1

**助手**：（运行校验脚本 → 输出预览，结束本轮）

即将创建以下活动，请确认：

**大活动**

| 字段 | 值 |
| --- | --- |
| 名称 | 中秋节4 |
| 活动类型 | 2（折扣） |
| 开始时间 | 2026-08-20T00:00 |
| 结束时间 | 2026-08-25T23:59 |
| 活动人群 | ALL（所有用户） |
| 预算 | 1212 元 |
| 集合优惠 JSON | {} |
| 操作人 | mcp-agent |

**商品活动（1 条）**

| # | POI | SKU | UPC | 商品优惠 |
| --- | --- | --- | --- | --- |
| 1 | 10003 | 3333 | xxxx33 | `{"price":0.7}` |

大活动与商品活动将在同一事务内创建，任一失败整体回滚。

确认请回复：**确认创建 中秋节4**
回复其他内容将取消本次操作。

**用户**：确认创建 中秋节4

**助手**：（调用工具 → 回显）

**大活动**

| 字段 | 值 |
| --- | --- |
| ID | 9 |
| 名称 | 中秋节4 |
| 活动类型 | 2（折扣） |
| 时间 | 2026-08-20 00:00:00 ~ 2026-08-25 23:59:00 |
| 人群 | ALL（所有用户） |
| 预算 | 1212 元 |
| 商品活动数 | 1 |
| 操作人 | mcp-agent |

**商品活动**

| ID | POI | SKU | UPC | 商品优惠 |
| --- | --- | --- | --- | --- |
| 14 | 10003 | 3333 | xxxx33 | `{"price":0.7}` |

说明：大活动与商品活动在同一事务内创建完成，商品活动自动继承类型并挂到 actId=9 下。

## 示例 2：跨字段冲突当场指出

**用户**：活动开始时间改为 2026-8-20 00:00（此前结束时间为 2026-8-15 23:59）

**助手**：开始时间已更新为 **2026-08-20T00:00**。但当前结束时间 `2026-08-15 23:59` 早于开始时间，无法创建，请同步给一个新的结束时间。

不要默默把结束时间改成某个猜测值。

## 示例 3：调用失败（事务回滚）

工具返回错误 `结束时间必须晚于开始时间`。

**助手**：创建失败：结束时间必须晚于开始时间。本次请求已整体回滚，**没有写入任何数据**。请给出调整后的结束时间，我会重新提交。

## 示例 4：用户要求演示而非创建

**用户**：组合创建活动的入参长什么样？

**助手**：只输出一份格式化后的 `tool_arguments` 示例并说明字段含义，不调用工具。用户没有明确写入意图时不写库。

## 示例 5：要求跳过确认

**用户**：直接创建，不用确认

**助手**：创建会写入线上数据，需要你先看一次完整入参。

（输出预览卡片并结束本轮）

即使用户明确要求跳过，也要完成一次预览 + 明确确认。

## 示例 6：确认时附带参数修改

**用户**：确认创建 中秋节4，不过预算改成 2000

**助手**：预算变更后与刚才的预览不一致，这次确认不能沿用。我重新生成预览：

（输出新预览卡片，预算 2000 元）

请回复“确认创建 中秋节4”确认新版本，或“取消”。

## 示例 7：取消

**用户**：先不建了

**助手**：已取消，未创建任何数据。

停止操作，不再追问。
