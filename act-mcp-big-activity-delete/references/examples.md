# 交互示例（用于对齐 HITL 行为）

## 示例 1：按名称删除（标准两轮）

**用户**：删除大活动 中秋节3

**助手**：（搜索到唯一匹配 → 读取详情 → 预览）

即将删除以下大活动，请确认：

| 字段 | 值 |
| --- | --- |
| ID | 8 |
| 名称 | 中秋节3 |
| 活动类型 | 2（折扣） |
| 时间 | 2026-08-10 00:00:00 ~ 2026-08-15 23:59:00 |
| 人群 | ALL（所有用户） |
| 预算 | 1212 元 |
| 商品活动数 | 2（将被级联删除） |
| 创建人 | mcp-agent |

⚠️ 此操作不可恢复，会同时删除该活动下的 2 个商品活动。

确认请回复：**确认删除 中秋节3（ID 8）**
回复其他内容将取消本次操作。

（结束本轮，等待用户）

**用户**：确认删除 中秋节3（ID 8）

**助手**：（调用 delete_big_activity(id=8) → 校验 → 回显）

已删除大活动 **中秋节3（ID 8）**，并级联删除 2 个商品活动。此操作不可恢复。

## 示例 2：名称命中多条

**用户**：删除中秋节

**助手**：找到 3 个名称包含“中秋节”的大活动，请用 ID 指定要删除的一个：

| ID | 名称 | 类型 | 时间 | 商品活动数 |
| --- | --- | --- | --- | --- |
| 8 | 中秋节3 | 折扣 | 2026-08-10 ~ 2026-08-15 | 2 |
| 9 | 中秋节4 | 折扣 | 2026-08-20 ~ 2026-08-25 | 1 |
| 11 | 中秋节预热 | 满减 | 2026-09-01 ~ 2026-09-08 | 0 |

给出 ID 后我会先展示详情和影响范围，再请你确认。

不要默认删除第一条或“最新一条”。

## 示例 3：含糊回复

**用户**：好

**助手**：请回复“确认删除 中秋节4（ID 9）”以执行删除，或回复“取消”。仅凭“好”我不会删除任何数据。

只追问一次，不要替用户做决定。

## 示例 4：取消

**用户**：先别删

**助手**：已取消，未删除任何数据。

停止操作，不再追问。

## 示例 5：要求跳过确认

**用户**：直接删，不用确认

**助手**：删除不可恢复，而且会级联删除商品活动。我可以马上执行，但需要你先看一次影响范围。

（随后输出预览卡片并结束本轮）

即使用户明确要求跳过，也要完成一次预览 + 明确确认。这是 HITL 的最低要求。

## 示例 6：目标已不存在

**用户**：确认删除 中秋节4（ID 9）

**助手**：删除失败：大活动不存在（ID 9），可能已被删除。本次没有产生任何变更。请确认 ID 是否正确。

不要重试删除，也不要把失败报告成成功。

## 示例 7：只想删部分商品

**用户**：把中秋节4 里那个 sku 4444 的商品活动删掉

**助手**：这是删除商品活动，不需要删除整个大活动。我会用 `delete_product_activity` 处理该商品活动；请确认商品活动 ID（或我先按 actId + sku 查询）。

不要在用户只想清理单个商品时删除整个大活动。
